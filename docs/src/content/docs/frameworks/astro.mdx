The component renders static HTML with no client JavaScript. It's the default export, and also exported by name: `import { WordHug } from "wordhug/astro"`.

## Props

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| children | text and elements | – | What to render, when there is no `text`. |
| `text` | `string` | – | Text to render instead of the children. Wins when both are given. Empty input renders nothing. |
| `as` | tag name | `"span"` | Element that wraps each group. |
| `class` | `string` | – | Class on each group wrapper. |
| `style` | `string \| null` | `"display: inline-block"` | Style attribute on each group wrapper. `null` removes it. |

## Children

Elements and `{expressions}` in the children stay where they are, and a group can contain them:

```astro
<p><WordHug class="nowrap">Buy [only <strong>{price}</strong> today]</WordHug></p>
```

Astro hands children to a component as rendered HTML, so the component reads brackets in the text only, and brackets inside an element are read within that element. Code, `<pre>`, `<script>`, `<style>` and hydrated islands are left alone, so islands still hydrate.

Use `text` when the text comes from a variable: `<WordHug text={post.title} />`.

## `wordhug()`

Returns the same output as an HTML string, with the text escaped, for `set:html`. It takes plain text, like the `text` prop. Options are `as`, `class` and `style`:

```astro
---
import { wordhug } from "wordhug/astro";
---

<p set:html={wordhug("Fresh bread [delivered daily]", { class: "nowrap" })} />
```

## Markdown and MDX

For content collections and `.md` or `.mdx` pages, add the [rehype plugin](/guides/markdown/) to Astro's markdown config, and writers can use brackets in their markdown:

```js
// astro.config.mjs
import rehypeWordhug from "wordhug/rehype";

export default { markdown: { rehypePlugins: [rehypeWordhug] } };
```

Astro 7 renders markdown with its new default processor, which doesn't run rehype plugins. Install `@astrojs/markdown-remark` so `rehypePlugins` work:

```bash
npm install @astrojs/markdown-remark
```

These docs are built that way: their own markdown goes through wordhug.
