---
title: Parsing rules
description: How wordhug reads brackets, nesting, whitespace and escapes.
---

Every framework, the HTML string and the markdown plugin follow the same rules.

| Rule | Input | Output |
| --- | --- | --- |
| `[...]` marks a group | `Hello [big world]` | `Hello <span>big world</span>` |
| Groups can nest | `[a [b c] d]` | `<span>a <span>b c</span> d</span>` |
| A bracket without a partner stays as text | `a ] b [ c` | `a ] b [ c` |
| Text touching a bracket stays attached | `(see [page 3])` | `(see <span>page 3</span>)` |
| Empty groups are dropped | `a [] b` | `a b` |
| A backslash makes a literal bracket | `\[sic\]` | `[sic]` |

In the table, `<span>` stands for the full wrapper, `<span style="display: inline-block">`.

## Whitespace

Runs of whitespace collapse to a single space, and whitespace at the start and end of the text and of each group is removed: `[  big   world ]` becomes a group containing `big world`.

In [markdown](/guides/markdown/), [Astro](/frameworks/astro/) children and [rich text](/guides/rich-text/), where the text already sits in HTML or nodes, only a group's edges are trimmed. Other whitespace is kept as written, so a space at the edge of `<em>` or `**…**` still separates it from the next word.

## Literal brackets

To show a bracket instead of starting a group, put a backslash before it. The backslash is removed. A backslash before any other character is kept as it is.

How many backslashes you type depends on where the text is written:

| Where | Write | Why |
| --- | --- | --- |
| JSX text, Vue and Svelte templates, Astro attributes | `Quote \[sic\]` | a backslash is literal there |
| A JavaScript string | `{"Quote \\[sic\\]"}` | the string needs its own backslash escaped |
| Markdown | `Quote \\[sic\\]` | markdown removes one backslash before a bracket |

## Elements inside groups

In React, Vue and Solid, the children can contain elements as well as text. Elements stay where they are, and a group can contain them: each element is one unit that is never split. Brackets inside an element are not read, so a group can't start in one element and end in another.

```tsx
<WordHug>Fresh bread for [only <strong>$3</strong> a loaf]</WordHug>
```

## Groups across formatting

In [markdown](/guides/markdown/) and [Astro](/frameworks/astro/) children, a group can start in one formatting element and end in another, as in `**a [b** c]`. `<strong>`, `<em>`, `<b>`, `<i>`, `<u>`, `<s>`, `<del>`, `<ins>`, `<mark>`, `<small>`, `<sub>`, `<sup>` and `<span>` are split at the bracket, so the group fits and every piece keeps its formatting:

```html
<!-- **a [b** c] -->
<strong>a </strong><span style="display: inline-block"><strong>b</strong> c</span>
```

A link, an element with an `id` or any other element can't be split. Then the brackets stay as text and a warning is reported: a vfile message from the markdown plugin, and a console warning in Astro development.
